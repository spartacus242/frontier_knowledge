## Restatement (my words, not the generator's)

Take several shipped vision-language models, each run under each of its image-input modes (plain resize, and every tiling / any-resolution setting). Feed each synthetic gratings and slanted edges, sweeping how fine the stripes are (counted per image AND per encoder patch), how faint they are, which way they point, and their phase. Ask a two-choice question each time and score it against chance. Then report: (i) the stripe fineness at which the model stops telling orientation apart at 75% correct, and the faintness threshold at each fineness; (ii) how that compares with the "half-a-cycle-per-patch" number implied by the patch grid; (iii) whether apparent success beyond that point is an artefact of the downsampling kernel; (iv) whether that per-arm cutoff predicts small-text / counting / chart accuracy better than pixel count or token count does.

3. There is a "nominal patch-Nyquist limit set by patch size and positional-encoding resolution" against which a ratio is meaningful (P4, limb ii). **CONTESTED as a sampling statement, on a source I opened**: `modeling_clip.py` lines 148-154: `self.patch_embedding = nn.Conv2d(in_channels=config.num_channels, out_channels=self.embed_dim, kernel_size=self.patch_size, stride=self.patch_size, bias=False)`. MY OWN REASONING, labelled as such: a conv with kernel = stride = p is a lossless re-blocking of the resized image followed by a linear map from 3·p² values (588 for p=14) to embed_dim; where embed_dim ≥ 588 (ViT-L/14's 1024 — a config value I recall and did NOT open) that map CAN be injective, so sub-patch structure up to the RESIZED-PIXEL Nyquist (0.5 cycles/pixel = p/2 = 7 cycles/patch at p=14) can pass this stage in principle. The patch grid is therefore not a Shannon sampling grid for image content; the sampling stage is the bicubic resize to the fixed or budgeted pixel grid (clause 1). "Patch-Nyquist" (0.5 cycles/patch) is a conventional reference, not a limit "set by patch size", and the positional encoding resolves token POSITION, not token CONTENT. I have NOT shown that any learned projection is full-rank — that is an empirical matter and is in fact close to what the candidate would measure. VERDICT ON THE CLAUSE: the question survives, because limb (ii) can be re-referenced to a correctly named nominal limit (resized-pixel Nyquist, or a stated conventional 0.5 c/patch) without changing the measurement; but as worded, limb (iii)'s "above-cutoff correct responding attributable to resize-kernel aliasing" conflates "above 0.5 cycles/patch" with "aliased", since responding between 0.5 and 7 cycles/patch needs no aliasing at all. Not fatal; a wording defect in a load-bearing limb.
