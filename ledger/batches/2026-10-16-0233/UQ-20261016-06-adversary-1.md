# UQ-20261016-06 — Adversary #1 log (Gate 4)

## Restatement (my own words)
Serve an open-weight LLM agent greedily, with seeds fixed, tool responses recorded-and-replayed, and the harness frozen. Default GPU kernels still produce slightly different numbers depending on what else happens to be in the serving batch, so two "identical" rollouts can diverge at some near-tie token. The question asks two things: (i) how much scatter in task success does this one leftover channel produce, measured as the difference between replicate scatter under default kernels with batch composition shuffled and replicate scatter under batch-invariant kernels; and (ii) does the shuffled-batch arm have a *lower average* success rate than the average over several fixed numeric paths (not merely a wider spread), and does that deficit grow with how long the task runs? The author's conjectured mechanism: errors in long agent runs are sticky (failure absorbs, success does not), so a rollout that hops between numeric paths at every step gets "more chances" to fall into an absorbing failure than a rollout that follows a single pinned path.

## Recommended verdict
**Provisional.** Nothing Unresolved, but novelty does not fully hold: the record missed arXiv:2506.09501 (NeurIPS 2025 oral), a direct prior on limb (i) that already quantifies batch-size/GPU-count-induced greedy accuracy variance and attributes it to FP reductions, and the lm-eval-harness issue trail shows limb (i) asked since 2023. Promote only if the canonical question is narrowed to the mean-shift/horizon limb, 2506.09501 is added as nearest prior, and the "more chances" mechanism argument is repaired or dropped (the pinned path meets the same number of near-tie tokens).
