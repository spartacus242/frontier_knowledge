## Restatement in my own words

Take one pretraining recipe at a size where several device layouts are possible. Run every combination of a few
layouts (different GPU counts, different micro-batch counts, different TP/PP/SP/EP sharding styles) crossed with a
few random seeds, keeping the data, the global batch contents and order, the seed and the number formats the same,
and admitting only layout changes that provably leave the mathematical objective alone. Then ask: treating layout and
seed as two random factors, how big is the layout-induced variance in (a) held-out loss at a fixed token budget and
(b) a pre-registered set of downstream scores, relative to the seed-induced variance — with an interval on the ratio?
If the ratio's upper confidence limit is below 1, call the training "layout-invariant"; otherwise report the size of
the excess and which layout axis carries it. Short version: *is "same recipe, different sharding" the same experiment,
and is the difference smaller than the noise the field already tolerates?*

### Free GitHub code search (primary source for my own technical claim)

`repo:NVIDIA/Megatron-LM` → `megatron/core/tensor_parallel/random.py` (commit 0900d92), docstring of `model_parallel_cuda_manual_seed`, quoted verbatim:

> "Three set of RNG states are tracked: default state: This is for data parallelism and is the same among a set of
> model parallel GPUs **but different across different model parallel groups**. This is used for example for dropout
> in the non-tensor-model-parallel regions. tensor-model-parallel state: **This state is different among a set of
> model parallel GPUs**, but the same across data parallel groups. This is used for example for dropout..."

and the seed construction:

> `offset = seed + 2718` / `tensor_model_parallel_seed = offset + tp_rank` / `# Data parallel gets the original seed.`

Scope check on my claim: this is the production code path of the stack the record leans on hardest, and it bites exactly
in the candidate's regime (fixed `--seed`, varying TP/DP degree). Consequence: with a stochastic regulariser active,
changing the TP degree changes the *set* of rank-keyed streams feeding the sharded activations, and changing the DP
degree changes which stream a replica draws from in non-TP regions. A layout change is therefore not only a change of
summation order: **it is also a re-draw of the realised randomness.** It does *not* bite for a dropout-free recipe with
a materialised initial checkpoint — but the record never restricts to that case.

### My own arithmetic (labelled as mine; computed locally, pure-Python F/chi-square quantiles)

Balanced one-way random-effects model, C configurations × S seeds, σ²_seed ≡ the within-configuration component. Pivot
R/(1+S·ρ) ~ F(df_A, df_E) with R = MS_config/MS_seed, df_A = C−1, df_E = C(S−1), ρ = σ²_config/σ²_seed (standard exact
Burdick–Graybill-type bound; I could not open a textbook source, so this is my derivation, not a quoted result). The
candidate's rule "one-sided 95% upper confidence limit of ρ below 1" then requires R < (1+S)·F_{0.05}(df_A, df_E):

| design | df_A, df_E | need R < | P(rule fires | system truly invariant, σ²_config = 0) |
|---|---|---|---|
| C=3, S=3 (the declared minimum) | 2, 6 | 0.207 | **0.18** |
| C=4, S=4 | 3, 12 | 0.572 | 0.36 |
| C=5, S=5 | 4, 20 | 1.034 | 0.59 |
| C=5, S=10 | 4, 45 | 1.927 | 0.88 |

Carrying the uncertainty rather than the point estimate: with df_A = 2 a variance component's 95% interval already spans
0.27× to 39.5× its estimate (χ²₂ quantiles 0.0506 / 7.378), which is what drives the first row. Method caveat: another
interval method (bootstrap, Bayesian, Satterthwaite) moves these numbers, but the binding constraint is df_A = C−1 = 2,
so the direction — *the declared minimum design can essentially never return the "invariant" branch* — is robust to method.
