# UQ-20261023-04 — Adversary #2 log (fresh context; first adversary's log not read)

## Restatement in my own words (before engaging the record's framing)

A nanopore sequencer running adaptive sampling looks at the first slice of each molecule, decides against a reference whether that molecule is wanted, and if not flips the voltage and throws the rest of the molecule away. So the reads you end up with were chosen by a rule that depends on what the molecule looked like at its start, compared to a reference you already suspect is wrong for your sample. The question asks two things. First: how wrong, and in which direction, are four specific numbers you would compute from the kept reads — the reference-allele share and heterozygote recovery at the loci you targeted, how many insertions/SVs you recover broken out by size, the shape of the repeat-length distribution, and per-site methylation fraction — relative to a run of the same library with the chooser switched off. Second: can you undo that distortion using nothing but what the run itself already wrote to disk — the stub of each thrown-away molecule, matched by read id to the record of whether it was kept or kicked, with the decision rule run again over those stubs to recover each molecule's probability of being kept. Scope is deliberately non-clinical: conservation/population, plant, environmental-microbial.

Put in the method field's words: adaptive sampling is informative selection on a per-molecule covariate, and the question is the magnitude and sign of the induced estimand bias plus whether a propensity is reconstructable post hoc.

## Nomination, justified by document kind (or declared a guess)

The clause I could not close is **C5**: whether a replay reconstructs the propensity for runs whose configuration changed mid-run. What kind of document could settle it: not a paper about adaptive sampling, but a **run-level artefact or a software specification** that (a) covers runs using readfish's optional dynamic-reconfiguration path or BOSS-RUNS' evolving decision masks, (b) varies the configuration during a run, and (c) **prints or writes a per-read record of which configuration was in force**. Neither readfish's `unblocked_read_ids.txt` (bare read ids) nor MinKNOW's AS Decisions CSV v0.1 (three columns, no timestamp) is that kind, on the record's own full reads of both. The right nominee is therefore a **BOSS-RUNS run artefact or its output specification** — the one implementation whose decision masks are known to evolve within a run — and I have **not opened any BOSS-RUNS output artefact**, so I am naming a document kind, not a document: this is a lead, not a checked source.
