## Restatement (my words, not the generator's)

Take HAL's released agent-run logs. Pre-declare a rule for which LLM calls / tool outputs in a trajectory were wasted, in the sense that deleting them from every later step's context would not change any later action; validate the rule against hand labels. Measure the wasted share of tokens and of dollars, split by solved vs unsolved runs. On the few cells where HAL varies the scaffold for a fixed model, ask whether that share belongs to scaffold, model or task (with CIs). Then ask whether ranking agents by cost-minus-waste reorders them beyond what plain total-cost ranking already does — i.e. is the waste share non-constant across cells.

## What the opened papers actually contain (evidence base for the table)

- arXiv:2512.02393 (Liu, Chen, Jabbarvand; Krishna, Sinha, Ganhotra — UIUC/IBM), opened. 4,000 trajectories = 500 SWE-bench Verified issues x 8 agent-model pairs in a CROSSED design (SWE-agent, OpenHands) x (DeepSeek-V3, DeepSeek-R1, Devstral-small, Claude Sonnet 4). Metrics include Loop Count and Average Loop Length ("the average number of actions involved before an agent decides to repeat a previously executed action"); nine anti-patterns from manual review of 600 trajectories: RepeatedView, ZoomOut, UnresolvedRetry, EditReversion, NoEffectEdit, etc. Attributes complexity descriptively to scaffold ("OpenHands trajectories are more complex", attributed to its system prompt) and model ("Stronger models produce a denser Graphectory"), tests task difficulty with Kendall's tau_b. Verbatim: "inefficiencies, although to a lesser extent, are prevalent in resolved instances as well" (section 3.4). No tokens, no dollars (cost appears only as a $2 cap and a remark that NoEffectEdit "waste[s] execution cost"), no formal variance decomposition, no re-ranking, HAL not mentioned.
- arXiv:2607.22585 (Vats, Golev — Sentient Labs; under review DL4C @ ICML 2026), opened. Fully crossed 3 harnesses (Goose, OpenCode, OpenHands-SDK) x 2 models x 50 Terminal-Bench Pro tasks = 300 trials. Tokens per solved task: Goose 28,142 / 36,950 vs OpenCode 1,147,740 / 1,546,977; verbatim: "harness choice shifts tokens-per-solved-task by 40x, while upgrading the model barely moves it (1.0–1.3x)"; bootstrap CIs (B=10,000) non-overlapping. Within-trajectory waste proxy: "no-action turns" (turns that neither modify a file nor issue a shell command), OpenCode 2.0–2.16 per task vs Goose 0.2–0.3, caveated that "a reasoning-only turn could in principle still be useful"; token cost of those turns asserted not measured. Pareto re-ranking of pass rate vs tokens/solved task. No ANOVA; HAL not used.
- arXiv:2509.23586v2 (Xiao, Gao, Peng, Xiong — PKU/ByteDance; FSE 2026), opened. Pilot: 100 Trae Agent (Claude 4 Sonnet) SWE-bench Verified trajectories manually inspected; waste taxonomy "useless, redundant, and expired information"; verbatim "waste is widespread in almost all trajectories"; one step 1,714 of 1,995 tokens waste. AgentDiet reduces input tokens "39.9%–59.7%" and cost "21.1%–35.9%" with no pass-rate loss. Rule is heuristic/LLM-judged, not counterfactual; one scaffold, one base model; no solved/unsolved split; no attribution; no re-ranking.
- arXiv:2601.14470v1 (Salim et al., Concordia; MSR 2026), opened. ChatDev x GPT-5, 30 tasks; tokens by phase (Code Review 59.4%); no waste category, no scaffold/model comparison. Adjacent only; shows "where tokens go" accounting is live but does not pre-empt.
