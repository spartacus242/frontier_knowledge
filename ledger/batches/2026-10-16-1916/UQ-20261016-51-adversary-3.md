## Restatement (my words, not the generator's)

When a benchmark question's text turns up in an open pretraining corpus, the copy may carry an answer. The candidate asks two things. (a) Of all corpus copies of an item, what share state the gold answer, state some other answer, state no answer, or expose the gold key itself as wrong — with CIs and an extractor error rate. (b) For items whose answer-stating copies mostly carry a non-gold answer, does an open-data model trained on that corpus score worse on them than on comparable never-seen items — so that contamination can depress a score rather than inflate it — and by how much would the reported score move if those items were dropped instead of kept?

## Recommended verdict

**Rejected** — Unresolved on attack 2 (Disguise: web pass could not be run → unresolved by default; and the sanctioned alternatives show the question is a one-class refinement of the already-tooled Dodge/Li/OpenCompass partition, with the "erroneous key memorised" half already in MMLU-Redux) and on attack 4 (the one-signed presumption, the prior-C anomaly and the population of the non-gold class all fail against opened sources).

What would promote it: (1) a completed eight-vocabulary web Disguise pass when search budget exists; (2) a reformulation that drops the "signed correction / one-signed presumption" framing, states itself as a sub-partition of the Li/OpenCompass "input-only contaminated" class into {no answer stated, non-gold answer stated}, measured on an indexed open corpus, restricted to benchmarks whose keys were not scraped from the same web sources and to corpora recent enough to contain model-generated solution traces (the only plausible large source of non-gold copies); and (3) for the causal limb, an injection arm — without which the question is limb (a) alone, which is a measurement and likely Low-novelty increment.

Single strongest killing point: the record's load-bearing novelty claim — "none found reports what the retrieved occurrence ASSERTS" — is false: Li's Contamination_Detector and the OpenCompass harness classify every retrieved web copy by whether it carries the gold answer and report accuracy on clean / input-contaminated / input-and-label-contaminated subsets (an input-contaminated subset already appears below clean in OpenCompass's own docs example), while in the candidate's named frame the non-gold class is structurally thin because MMLU's keys came from the same web sources (MMLU-Redux) and prior C's GPQA copies are gold-carrying dataset uploads — so the candidate reduces to sub-partitioning one existing class with an unidentified causal limb.
