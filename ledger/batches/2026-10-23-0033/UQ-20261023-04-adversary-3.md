## Restatement in my own words

A nanopore sequencer running adaptive sampling looks at the first ~400 bases of each molecule, asks "does this look like it comes from somewhere I care about", and for the molecules that fail the test it reverses the voltage and throws the rest of the molecule away. So the reads you end up analysing are not a random sample of your library — they are the ones that passed a test defined by a reference genome. The question asks: **for four specific quantities people compute from the surviving reads — the reference-allele fraction and heterozygote recovery at target sites, insertion/SV recall split by size, the repeat-length distribution, and per-site methylation fraction — which way and how far does that test push the answer; and can you undo it afterwards using only what the run itself kept (the stubs of the thrown-away reads, plus the per-read record of what the machine did, with the decision rule re-run over those stubs to recover each molecule's chance of survival)?** It is a question about selection on acquisition, where the selection is irreversible, asked in non-clinical settings (conservation, plant, environmental microbial genomics) where the decision reference is divergent from the sample by construction.

Two things the question does **not** do, and I grade accordingly: it does not assert the direction of the bias (it asks for a *signed* bias), and it does not assert that the bias is large (Gate 1 declares magnitude the measurand). Those are measurands, not presuppositions, and attack 4 does not reach them. I declare that exemption rather than grading around it.

## The single strongest killing point (sourced, with the artifacts named)

Both are false on instances the record either located itself or had in the ecosystem it opened:

The record's own query 11 says it "located the AS Decisions CSV and **AS Timings** specs", then counted only the three-column decisions file in the universal.

The record opened `_read_until_client.py` in this same repository, found `unblocked_read_ids.txt` to be a bare list of IDs, and concluded the log "carries no covariate whatsoever".

So three of the four "exact missing fields" are already printed today; exactly **one** is genuinely absent from everything I opened — the **decision target / matched reference position** (which contig and coordinate the first chunk aligned to). Consequences: (i) V1's correction limb was not false as stated, so **the one reformulation Gate 1 permits was spent on a non-problem**, and V2's "i.e." gloss defines "the run's own retained output" as a *strictly poorer* route than what the same run already retains; (ii) Gate 3's headline action shrinks from a four-field spec rewrite to one field; (iii) the record's R2 ("weakest limb") is largely discharged in the candidate's favour. None of this falsifies a clause V2 needs, so it does not reach Unresolved on 1/2/4 — it is a construction-and-significance defect, and the promotion condition is to re-pose the correction limb against the covariates that exist.
